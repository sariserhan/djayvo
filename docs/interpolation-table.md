# Precomputed coefficients for common cold note starts

2026-10-19. Shared sampled voices now copy a read-only 65×16 coefficient table
when their interpolation cutoff is exactly 0.94. This removes repeated filter
trigonometry even when the per-voice cache is empty. The existing cache still
handles repeated cutoffs, and other cutoffs retain the original anti-alias
calculation. This is an audio-engine cost reduction; musical quality is **NOT RUN**.

The table is constant C++17 data generated by the standard-library-only
[generator](../scripts/prepare_interpolation.py). It preserves the original
float storage before double-precision normalization. It requires no runtime
Python, static constructor, lazy initialization, lock, allocation or platform API.
Note state resets before either optimization. The C/C++ interfaces, voice layout,
sample bank, arrangements and browser controls are unchanged.

The browser creates its instrument worklet after resuming the audio context.
Moving filter calculations to that worklet's constructor could still consume an
active audio thread. The compiled table avoids adding such initialization work.
It occupies 4,160 bytes of coefficient data; the live WASM grew by 4,206 bytes.
Other instrument setup and filter misses still cost time. This is not a complete
startup, callback deadline or physical latency solution.

## Measurements

The [empty-cache probe](evidence/interpolation-table/probe.cpp) resets the Voice
before every timed start. Each run checks 6,000 notes against fresh voices and
saves 1,536,000 Float32 attack/release samples. Three paired runs on each platform
compare the retained `924eb61` library with this revision. Every PCM file matches,
including across Mac and Linux; maximum and RMS waveform differences are zero.
Resetting the voice cache does not flush CPU or filesystem caches. No first call
or outlier is discarded, and timing only covers `Voice::start`.

Median of three per-run medians, microseconds:

| Platform / empty-cache sequence | Before | After |
| --- | ---: | ---: |
| M5, fixed pitch | 5.416 | 0.083 |
| M5, changing pitch | 5.083 | 0.083 |
| M5, changing rate/instrument | 5.084 | 0.083 |
| Linux ARM64 VM, fixed pitch | 8.148 | 0.250 |
| Linux ARM64 VM, changing pitch | 8.069 | 0.250 |
| Linux ARM64 VM, changing rate/instrument | 8.234 | 0.250 |

The first candidate Mac call still took 19.458 µs; its later two process starts
took 1.458/1.625 µs. Linux first calls took 5.614–6.903 µs. The mixed sequence
still computes non-common filters: median per-run p95 is 6.292 µs on Mac versus
5.709 before, and 10.482 µs on Linux versus 10.607 before. No improvement in
that tail is claimed. Very small timings approach clock resolution; these ratios
must not be presented as complete-engine speedups.

The native 600-virtual-second load repeats the same 32-voice, 13-patch program
60 times. All 225,000 blocks and event frames match the retained reference;
zero C++ `new` allocations and zero blocks above 2.667 ms were observed. Maximum
block time was 1.266 ms; wall time was 10.117 seconds, similar to the previous
10.195 seconds. This is not a meaningful demonstrated throughput improvement,
and the earlier [deadline failures](live-deadline.md) remain retained.

## Evidence and reproduction

The permanent core test compares all 1,040 stored coefficients with the original
formula. The existing 756-case regression checks reused/fresh voices across
rates, instrument changes, velocity/takes, routing and releases. External
before/after comparisons provide a separate audio reference.

The [WASM comparison](evidence/interpolation-table/wasm-check.mjs) checks 1,170
old/new live-engine notes across five rates, thirteen patches, six pitches and
three velocities, including cold initialization and note-off at frame 256.
All 1,198,080 stereo frames match exactly. The normal remix suite also checks
seven fixture styles and four already-consented owner seeds. Saved-score replay
checks fourteen scores, exact event traces and 75 master/stem WAVs per platform.

Use fresh output prefixes/directories for reruns; old evidence and recordings
must be preserved. From the repository root:

```sh
python3 scripts/prepare_interpolation.py > /tmp/djayvo-full-band.inc
cmp core/instruments/full_band_interpolation.inc /tmp/djayvo-full-band.inc
cmake --build build-mac -j 4
ctest --test-dir build-mac --output-on-failure
cmake --build build-mac-sanitize -j 4
ctest --test-dir build-mac-sanitize -R '^(core|live_instruments)$' --output-on-failure
c++ -std=c++17 -O2 -I core/include docs/evidence/interpolation-table/probe.cpp \
  build-mac/libdjayvo_core.a -o /tmp/djayvo-cold-note-probe
/tmp/djayvo-cold-note-probe /tmp/djayvo-cold-note-new
python3 docs/evidence/interpolation-cache/replay.py build-mac/djayvo_remix \
  /tmp/djayvo-table-replay-new
sh scripts/web_build.sh
node apps/web/tests/wasm.mjs
node docs/evidence/active-vocals/wasm-check.mjs
node apps/web/tests/worklet-load.mjs
DJAYVO_BROWSER=webkit node apps/web/tests/worklet-load.mjs
```

The prior library and WASM are retained under `renders/interpolation-table-20261019`.
For a new baseline, build `924eb61` separately and link the probe to that library.

isolated project VM, retained prior build and a new candidate build. Its fixed
artifact paths identify this study; change them for a rerun. The existing
[Linux browser helper](evidence/worklet-load/linux-run.sh) uses a cached image,
no container network, and a local PulseAudio null sink. These are ARM64 VM tests,
not a rerun on the owner's physical Intel Linux computer.

[measure.py](evidence/interpolation-table/measure.py) independently verifies the

hashes, then writes [measurements](evidence/interpolation-table/measurements.json).
