# Music DNA: richer song understanding without downloading recordings

2026-10-23. Owner requested track-specific musical interpretation, reusable descriptions, and composition driven by playlist patterns.

## Behavior

During song planning, every identified favorite is considered in batches of six. Canonical track/artist pairs can contribute specific sound details; artist-only or unstructured entries are capped at low confidence. The existing local/CUDA lyric planner interprets energy, pace, instrumental texture, groove, instruments, production, vocal delivery, mood, arrangement and sung language. It does not fetch, listen to, download or train on reference audio. Descriptions are estimates from model knowledge and catalogue context, not acoustic measurements or verified musicological facts.

Only familiar/medium-confidence sound descriptions contribute detailed traits. Low-confidence, genre-only and unknown entries retain their catalogue contribution but have empty sound fields. Unsupported vocabulary is discarded. Malformed descriptions receive one bounded retry; entries that still cannot be validated are explicitly unavailable, contribute no invented traits, and are eligible for another attempt on the next generation. Missing/duplicate indices cannot attach a description to the wrong song.

The full genre distribution remains authoritative. Within the primary genre, descriptions form groups by energy, pace and texture. A seeded, count-weighted choice selects one group for a take; conflicting groups are not averaged together. The songwriter receives its strongest supported traits and up to 12 compatible examples. Pace narrows the existing permitted tempo range; validation enforces that range. The selected rhythm/texture/production/vocal/arrangement brief is placed before optional prose in the singer's 512-character caption, and survives style retries. An instrumental favorite never removes the generated song's singer.

All descriptions and confidence/basis fields remain in the owner's saved plan, together with the chosen group, counts and composition guidance. The next local or hosted request reuses matching descriptions from that owner's last 50 successful plans, isolated by billing environment and product. Reuse requires the same reference, catalogue genre, schema version and model revision; unavailable or invalid entries are reconsidered. Public listeners receive neither these descriptions nor the source favorites. This uses the existing private `song_plan` column; no new migration, cache service or dependency is needed.

## Verification

- **PASS:** 38 Python DNA tests, eight singer tests and 11 worker tests. Description/planner checks cover every favorite beyond the songwriter's 12 examples, late-list genre majority, confidence suppression, unsupported tags, malformed-output fallback, tempo enforcement, coherent group variation, model/version/genre cache invalidation, caption propagation, style retries, languages and lyrics.
- **PASS:** TypeScript and 30 isolated PostgreSQL/process/API tests cover local and hosted cache transport, restart persistence, owner/billing/product isolation, public redaction, credits, cancellation, failure and settlement recovery. No live charge or provider call is made by these fixtures.
- **PASS, actual local model:** the evaluation list contains ten named multilingual songs and twenty deliberately generic genre-only controls. All ten named songs received model-estimated sound descriptions; all twenty controls kept unknown sound fields and languages. Two subsequent plans reused all 30 records with zero new description calls, taking 33.6 and 59.5 seconds including local model loading/songwriting. Different seeds selected electronic and mixed-texture groups at 108 and 112 BPM; both plans preserve all favorites and carry the selected traits into the singer caption. These are planning times, not total song-generation times. [Receipt](evidence/dna-sound-profiles/local-model.json). Earlier trials exposed schema-label and vocabulary errors. A concrete known/unknown example and a boolean recognition field resolved the observed classification failures; fixed validation/fallback covers residual errors. The songwriter also confused relative reference intensity with the fixed genre-energy contract label, so that label is now filled from the authoritative direction, like singer identity, while tempo/content/style checks remain enforced. The interrupted/rejected diagnostic runs were retained; none rendered audio. Ignored diagnostics are under `build-playlist-taste/sound-profiles-v*/`.
